# 04 背景流光与交互反馈

> 来源：徒步小记原生版 `ui/Aurora.kt`、`ui/AppChrome.kt`、`ui/SafeTap.kt`、`ui/Toast.kt`、`ui/GlassWidgets.kt`。
> 这套语言里"动"的部分：背景怎么流、按下去什么反馈、点错了怎么办。

---

## 一、背景流光 AuroraLayer（1:1 搬 Web `.aurora-bg`）

### 三颗光斑

| # | 位置 | 直径 | 浅色 | 深色 | 周期 |
|---|---|---|---|---|---|
| ① 蓝 | 左上（-22vw / -10vh） | 95vw | `#60A5FA × 0.30` | `#6366F1 × 0.26` | 4.4s |
| ② 粉 | 右下 | 100vw | `#F472B6 × 0.26` | `#BE185D × 0.24` | 4.8s |
| ③ 青 | 中上（16vw / -6vh） | 80vw | `#2DD4BF × 0.22` | `#0F766E × 0.22` | 3.6s |

每颗都是径向渐变圆（中心 → 68% 处透明）+ 三个关键帧的位移/缩放往返，`RepeatMode.Reverse` 让它到 100% 原路退回。

**为什么周期必须互不相同（4.4 / 4.8 / 3.6）**：三颗如果同步放大缩小，看起来是整块在"呼吸"，不是"流动"。周期互质才永远对不上拍子。

### 两个实现要点

1. **只动 `graphicsLayer` 的平移/缩放**，位图只栅格化一次，之后交给合成器搬——零重绘、零重新采样。背景每帧真重绘的话，采样它的 N 层玻璃都要跟着重采样，帧率直接掉。
2. **动画值在绘制阶段读**（`Spot` 传 lambda 而不是结果）。在组合期读会让每个动画帧都重组、重建 3 个 radialGradient（60fps = 每秒 60 次无效重组 + 180 次分配）。

上方那颗青色原来圆心在屏幕外，只露极淡一条边——放大直径并把 baseY 移到 -6%h 才看得见。

## 二、底栏：整条语言里最"液态"的一块

### 结构（兄弟节点，绝不嵌套）

```
Box（容器）
 ├─ ① 底栏玻璃本体（唯一有离屏层的，但它自己不动，也不含胶囊）
 ├─ ② 选中胶囊（会动 → 纯自绘，零离屏）
 └─ ③ 一格格内容 + 点击区（indication = null，无涟漪）
```

胶囊和底栏**必须是兄弟**。之前把胶囊嵌进底栏离屏层里，移动时旧位置清不干净 → 屏幕上留方块。

### 胶囊形变（squash & stretch）

公式思路来自 Kyant0/AndroidLiquidGlass 的 `LiquidBottomTabs`：

| 量 | 值 | 校准过程 |
|---|---|---|
| 按住放大 | **1.39 倍** | 官方配方。1.04 太拘谨，看不出"被捏起来" |
| 速度形变上限 | **±3.5%** | 官方 ±20% 演示动画量级 → 用户"太夸张，一直不和谐地跳"；0.025 → 3.5% 用户"太不明显"；0.06 → 8% 用户"从 8 调到 12%"；最终 0.09/0.12 但加了独立的速度平滑，实际体感收敛到一丁点 |
| 整条底栏跟手位移 | 封顶 4dp | EaseOut，松手弹回。让"被拽的是整条"比"只有胶囊在动"真实 |
| 回弹 | 临界阻尼 dampingRatio = 1 | 直接躺平，不过冲 |
| 按压反馈底座 | **不要** | 用户："把按压底删掉，不需要"——不要变色块，只留非等比形变 |

### 交互细节

- **按住即拖**：按下后移动超过系统 touch slop（约 8dp）就接管，不再等 500ms 长按。用户原话："那个延迟让跟手从一开始就输了半拍。"
- **再点一次当前 tab** → 发 reselect 信号（自增计数），各页面监听后回最上层（记录页还会重置分页）。
- 图标全部 **Filled**，不用 Outlined（同样 21dp 下实心看着大）。
- **底栏不要涟漪**：胶囊本身有按下凸显，涟漪在玻璃上就是一块方块。
- 切页时不要在 drag 回调里 `animateTo`——用的是 `liveCurrent` 而不是首次组合时的 `current`，否则拖到概览松手会跳回去。

## 三、按压反馈（通用）

| 控件 | 反馈 |
|---|---|
| 平面按钮 | 缩放 0.97，白膜 0.10 → 0.20，径向柔光（中心按在中上部） |
| 玻璃表面 | 缩放 0.985（变小），整体提亮白 0.10 |
| 液态胶囊 | 放大 1.39 + 上浮 1.5dp + squash&stretch + 径向按压高光 |
| 底栏格子 | 非等比形变 + 轻震动，**无涟漪、无变色底** |

**震动**：`HapticFeedbackConstants.VIRTUAL_KEY`，偏好可关，任何异常吞掉——震动失败绝不该影响点击本身。

## 四、安全点击（点一下就闪退的根治）

原生版 100 多个可点区域，onClick 直接跑在主线程事件分发里——Room 查询、文件读写、JSON 解析、Uri 权限、null 解引用任何一句抛异常都会冒到 Looper 上杀进程。

**解法：在事件入口统一兜，不逐个猜哪个 handler 有雷。**

`SafeTap.run`：
- 异常不杀进程
- 底部 Toast "操作出错了：xxx"，用户能截图告诉你哪一步炸了
- 堆栈写进 `filesDir/soft_error.txt`，诊断导出可见

`safeClickable`：
- `indication = null` —— 默认涟漪颜色取 onSurface（浅灰深白）、边界是节点矩形，扩散后要几百毫秒才淡出，在玻璃/圆角控件上就是"冒出一块方块"
- **不传 `interactionSource = null`**，改成 `composed` 里 remember 一个稳定实例。传 null 时 Compose 走"临时新建"分支，在点击密集页面有概率在事件分发阶段抛异常

⚠️ 这只兜点击处理函数内部的异常，兜不住重组阶段的异常——composable 里依然不许做重活。

## 五、Toast

- 1:1 对齐 Web 的 `_createToast`：背景不透明（不是透明底），深色胶囊 + 白字。
- 用 Popup 而不是普通 Toast，保证**弹窗打开时 Toast 盖在弹窗之上**。
- 关闭弹窗时不要顺手关 Toast。
- 危险操作后的提示走这里，不打断当前流程。

## 六、弹窗收口

- **统一"关闭"按钮，X 去掉**：所有弹窗底部一个收口按钮，位置/样式一致。
- 标题：16sp，全站唯一写法 `DialogTitle`。
- 正文：14sp / 行高 21sp，浅 `#1F2937` / 深 `#D1D5DB`。
- 按钮文字：15sp，比容器字号齐平或大一号，不要小一号。
- 语义三套：危险 / 实心危险 / 正向，见《03 液态玻璃材质》第七节。
- **弹窗平面化**：用户"现在这个虚假立体感不好看"——去掉顶部漫反射带、内壁棱、轮廓暗线、按下提亮，只留一层填充 + 一条极细边。大面积玻璃上堆光影会显得"鼓起来一块"。

## 七、反馈层常见错误

| 错法 | 后果 |
|---|---|
| 底栏胶囊嵌进底栏玻璃里 | 移动残留方块 |
| 长按 500ms 才接管拖拽 | 跟手慢半拍，用户明确否掉 |
| 底栏/胶囊用默认 24dp 阴影 | 细长条糊出方形灰影 |
| 按钮贴图默认涟漪 | 玻璃上冒出方块 |
| 动画值在组合期读 | 60fps 无效重组，掉帧 |
| 弹窗弹出后 Toast 被盖住 | 用户看不到反馈 |
|  onClick 直接裸跑 | 一句异常杀进程 |
