# 05 踩坑铁律（拿返工换来的）

> 来源：徒步小记原生版 143 版迭代里，源码注释标 ★ 的教训汇总。
> **每一条都对应一次真实的返工。** 做新项目时先读这篇，能省掉同样的坑。

---

## 铁律 1：玻璃不许削弱换稳定

**原话：** "我的折射呢？？？？"

为了修"方块"把底栏折射删了改成自绘 → 用户立刻发现。
正确顺序：保住玻璃本体 → 查附加物（离屏层、阴影、裁剪、缩放链、自采样）→ 只改那个出问题的附加物。

**降低玻璃效果是最后一步，不是第一步。**

---

## 铁律 2："方块"的六个真凶（按出现顺序）

同一个视觉 bug 修了六次，每次以为找到了，结果下一个才是：

| 次 | 真凶 | 修法 |
|---|---|---|
| 1 | 点击涟漪（浅灰/深白，矩形边界，几百ms 淡出） | 全站 `indication = null` |
| 2 | 按压缩放改 Modifier 链长度 → 重建渲染层，旧离屏层残留 | `graphicsLayer` 常驻，只改参数 |
| 3 | `Shadow.Default` 24dp 半径 > 底栏半高，上下叠成方块灰影 | 底栏/胶囊 `showShadow = false` |
| 4 | 胶囊用 `Modifier.clip(shape)` 创建矩形离屏层，和父离屏层叠 | 改用绘制阶段 `clipPath` |
| 5 | 浮层玻璃是内容层的子节点，被录进 backdrop → 自折射 | 改成兄弟节点，画在之后 |
| 6 | 弹窗在 `drawBackdrop` 之外又加 `.clip()` = 第三层离屏 + 11dp blur | 删掉多余 clip，库已按 shape 裁 |

**排障口诀：先查离屏层数量。**

---

## 铁律 3：`Modifier.clip` 是绘制阶段的毒药

- 底层是 `graphicsLayer { clip = true }` → 矩形离屏层。
- 玻璃叠玻璃时，矩形里没画到的空白被合成出灰底 = 方块。
- 正解：`clipPath(outline) { drawGlass() }`（纯 Canvas 指令，零离屏层）。
- 但 `drawContent()` **必须放在 clipPath 外面**——在裁剪块里调 drawContent 会在真机绘制线程抛异常闪退。

---

## 铁律 4：Modifier 链结构必须恒定

按下/抬起如果让 Modifier 链时而多一层、时而少一层 → 节点重建渲染层 → 旧位图清不干净。

**所有会变的状态都放进常驻的 `graphicsLayer` / `remember`，只改参数，不改结构。**

同理：`effects` lambda、`shapeProvider`、`highlightProvider` 都要 `remember`——`DrawBackdropElement.equals` 比的是 lambda 引用，每次重组新建就判不等，绘制缓存全废、滚动掉帧。

---

## 铁律 5：绘制阶段抛异常 = 闪退

Canvas draw 阶段抛异常时，半块已经画到屏幕上了，catch 都来不及体面收场。所以：

| 危险点 | 守卫 |
|---|---|
| `RuntimeShader` 软件渲染不支持 | `gpuEffectsUsable` 早退，不"试一下再 catch" |
| AGSL 设备现编失败的驱动 | 第一次 catch 后 `lensBroken = true` 永久跳过，用 `@Volatile` 不用 state |
| `RenderEffect` 个别 OEM 抛 | blur 包 try，失败只少点毛感 |
| Path 在极端尺寸抛 | `if (w > 0.5f && h > 0.5f)` 才构造 |
| Room/文件/JSON 在 onClick 抛 | `SafeTap.run` 统一兜 |
| composable 里做重活 | 不许。重组阶段兜不住 |

---

## 铁律 6：自采样 = 越糊越脏

弹窗挂在页面 composable 内部时，它本身就是 `contentBackdrop` 那棵子树的一个节点。用它做背景模糊 = 采样包含自己的纹理 → 第一帧还行，之后每帧把自己再糊一遍 → 整块变成越来越糊的色块（用户看到的是"模糊层盖住屏幕"）。

**解法：`LocalInContentLayer` 标记，host 内部为 true，弹窗遇到 true 退回实色膜。只有画在 host 之外的顶层弹窗才享受真模糊。**

同理，页面里的卡片必须采样 `bgBackdrop`（纯背景），采样内容层就是递归。

---

## 铁律 7：模糊要克制

用户连着三轮说"太模糊"：

- blur 基数 3dp → 1dp，封顶 10dp（弹窗 frost 0.8 原本算到 11.4dp，大半径吃 GPU，也是崩溃嫌疑）
- frost 只负责"加一点毛感"，玻璃质感交给折射和边缘
- 模糊过头 = 雾；白膜过头 = 白板。两者都不是玻璃

**读数：卡片要又糊又白（正文压上面），浮层要糊但不白（要看得见背后内容）。**

---

## 铁律 8：白玻璃压白底必须有暗线

白描边只是高光，压在白背景/白弹窗上整块隐身——"看起来像没有按钮"。

每一层自绘玻璃都要配一条 `Black × 0.05~0.09` 的 1dp 轮廓暗线把形状"扣"出来。深色模式收小到 0.16~0.22。

---

## 铁律 9：按钮平面化，但底栏保液态

用户："所有的按钮也换为平面，所有设计语言统一为平面。"

- 按钮：一张薄面 + 一条细边，零 shader、零离屏。
- 例外：底栏那颗胶囊走 `glassPill`，不受影响。
- 参数保留兼容：原调用点一行不改，只改内部实现。

**"统一"不等于"全部同一种材质"——而是每一类控件只有一种写法。**

---

## 铁律 10：设计值集中定义，不散落

自查发现 14 种圆角、18 种字号、27 处硬编码危险红、8 种弹窗宽度、4 种限高、7 处裸 Indigo。

**一个值只能有一个源头。** 新增组件先查档位表，不许拍脑袋写新数字。配静态扫描脚本（`designcheck.py`）挡住漏网的。

---

## 铁律 11：文字黑白，装饰彩色

"app 不用全是黑白的，色带什么的就正常加颜色" + "只需存在白色字和黑色字"——两句看似矛盾，其实是明确分工：

- **文字/图标**：只有黑白 + 透明度
- **背景、色带、图标着色、进度、选中态**：正常用彩色
- 靛蓝是强调色，绿色只给正向，红色只给危险，紫色不参与正向语义

---

## 铁律 12：性能不是优化项，是生存项

玻璃项目的崩溃几乎都来自"层数 × 重绘频率"：

- 同屏 10 个玻璃按钮 = 10 shader + 10 离屏 ⇒ 崩 → 平面自绘
- 背景每帧重绘 ⇒ N 层玻璃跟着重采样 ⇒ 掉帧 → 只动 graphicsLayer
- 动画值组合期读 ⇒ 60fps 无效重组 ⇒ 掉帧 → 传 lambda 绘制期读
- 连续启动崩溃 ⇒ CrashGuard 打开 `forceStatic`，全站静态玻璃兜底

**先算同屏层数，再决定用哪种玻璃实现。**

## 一页速查：出问题时依次问

1. 玻璃本体还在吗？（不许靠删玻璃修 bug）
2. 有几层离屏？（clip / shadow / innerShadow / backdrop 自己）
3. Modifier 链结构变了吗？
4. 浮层是兄弟节点还是子节点？
5. 有自采样吗？（弹窗在 host 内部？卡片采样内容层？）
6. 当前设备走到哪档？（`tierLabel()`）
7. 阴影半径是不是超过控件半高？
8. 白玻璃有没有轮廓暗线？
9. 模糊/白膜是不是过头了？
10. 同屏有几块玻璃？重绘频率多少？
